## Global requirements

### Tech constraints
- **No framework, no build step.** Plain HTML + CSS + vanilla JavaScript.
- **Must work by double-clicking `index.html` (file://) with no internet.** The talk might happen on bad Wi-Fi. This means:
  - **No ES modules** (`type="module"` breaks on file://). Use classic `<script>` tags in dependency order, each file wrapping its code in an IIFE and exposing at most one namespace on `window.NN`.
  - **No `fetch()` of local files.** Model weights and any data are shipped as `.js` files that assign to `window.NN.data.*`.
  - No external CDN libraries. Everything self-written (Canvas 2D + SVG is enough).
  - Fonts: load from Google Fonts but with solid fallback stacks so the site still looks right offline.
- Rendering: Canvas 2D for animations with many elements (network, particles, drawing pad); SVG for diagrams with few elements (neurons, mapping). Always scale canvases by `devicePixelRatio`.
- Performance: steady 60 fps on a mid-range laptop. Pause all animation loops on slides that are not visible.
- Accessibility floor: visible keyboard focus, `prefers-reduced-motion` respected (replace continuous animations with static states, keep interactions working), text contrast ≥ 4.5:1.

### Stage and scaling
- Fixed logical stage of **1920 × 1080** (16:9), scaled with CSS `transform: scale()` to fit the window, letterboxed, centered. All slide layout is designed in stage pixels.
- Minimum on-slide font size: **28px** in stage pixels (it must be readable from the back of a classroom on a projector). Headings 64–96px.
- Max 25 words of visible text per slide, except slide 8 (the toolkit list).

### Navigation and presenter features
- Next: `→`, `Space`, `PageDown`, click on the empty area of the stage (not on interactive controls), swipe left.
- Previous: `←`, `PageUp`, swipe right.
- **Fragments:** slides can have steps revealed one at a time. "Next" reveals the next fragment first, then moves to the next slide. "Previous" hides fragments in reverse.
- `F`: toggle fullscreen. `N`: toggle speaker notes panel (overlay at the bottom, semi-transparent, shows the "Say" text for the current slide and a timer). `R`: reset the current slide's interactive to its initial state. `Home` / `End`: first / last slide.
- Keys `0`–`9` on slides 6, 7 and 9: load a sample digit (presenter safety net if live drawing goes wrong). These keys must not trigger anywhere else.
- URL hash routing: `#3` opens slide 3. Updating slides updates the hash.
- Thin progress bar along the bottom edge of the stage. Slide number in the bottom-right corner, small, muted.
- Keyboard events must be ignored while a slider or input is focused, except `Esc` (blurs the control).
- Interactive controls (sliders, buttons, drawing pad) must never trigger slide navigation on click/drag.

## Design system

### Concept: fluorescence microscopy
Neuroscientists see real neurons through a fluorescence microscope: dark ink-blue field, cells glowing in dye colors, and a bright flash when a neuron fires (calcium imaging). The whole deck uses that visual language, so biology slides and the artificial network share one look. That is the point of the talk: **it is the same idea**.

**One bold thing:** the **firing glow**. Whenever any neuron (biological or artificial) activates, it flashes in warm amber with a soft bloom. Everything else stays calm and quiet so this moment stands out.

### Color tokens (`css/tokens.css`)
| Token | Hex | Use |
|---|---|---|
| `--ink` | `#10162E` | stage background (deep microscope-field blue, not black) |
| `--ink-raised` | `#18203F` | panels, control tracks, notes overlay |
| `--paper` | `#E9ECF5` | main text |
| `--muted` | `#8E97B8` | secondary text, inactive connections |
| `--fire` | `#FFB547` | firing / activation / high probability (the signature) |
| `--stain` | `#C59BFF` | biological structures (dendrites, cell body, axon) |
| `--dapi` | `#6E8BFF` | positive weights, signals in transit |
| `--cherry` | `#FF5A7A` | negative weights, errors, loss |

- Activation brightness = interpolate from `--ink-raised` to `--fire` by activation value 0…1.
- Weights: color by sign (`--dapi` positive, `--cherry` negative), opacity and line width by magnitude.
- A very subtle radial vignette on the stage background is allowed. **No** gradients as decoration, **no** drop shadows on panels, **no** identical rounded cards.

### Typography
- Headings: **Bricolage Grotesque** (700–800), tight letter-spacing (-0.02em). Fallback: `"Segoe UI", system-ui, sans-serif`.
- Body and labels: **Atkinson Hyperlegible** (400/700). Chosen because it was designed for legibility, which matters on a projector. Fallback: `system-ui, sans-serif`.
- Numbers inside the tensor grid only: **IBM Plex Mono**. Fallback: `ui-monospace, monospace`. Not used anywhere else.
- Sentence case everywhere. No all-caps labels, no eyebrow labels above headings, no `→` glued onto button text, no "A · B · C" meta strings.

### Layout
- Default slide layout: text column on the left (~38% width, left-aligned, generous left margin of 140px), interactive area on the right (~55%).
- Slide 7 (the network) uses the full width; its heading sits small at the top left.
- Title and final slide: text left-aligned, large, with the animated background filling the stage.

```

+--------------------------------------+     +--------------------------------------+
| Heading                              |     | Inside the network                   |
|                  +----------------+  |     | [pad]  o o o    o o   o 0 ====       |
| short text       |  interactive   |  |     | 28x28  o o o    o o   o 1 =          |
| point            |  area          |  |     |        o o o    o o   o 7 ========== |
| point            |                |  |     |        784      64 32  10 outputs    |

```

### Motion rules
- Non-user-triggered motion only where it explains something (signals traveling, a neuron firing). No fade-and-slide-up entrance on every element.
- Slide transition: quick crossfade, 250ms. That is all.
- Interactive response: immediate (< 16ms to start reacting), easing `cubic-bezier(.2,.8,.2,1)`.
- With `prefers-reduced-motion`: no particles, no traveling pulses; neurons change brightness instantly; everything still interactive.

### UI controls
- Custom-styled range sliders: thin track `--ink-raised`, thumb `--paper`, filled part `--dapi`. Value shown next to the slider in body font.
- Buttons: text buttons with a 1.5px `--muted` outline, radius 6px, hover fills `--ink-raised`. Primary action outline in `--fire`.
- Every control has a visible focus ring (2px `--fire` outline, 3px offset).

### T03 — Title slide: living network background (slide 1)
A canvas filling the stage behind the title: ~70 nodes drifting slowly, connected by thin `--muted` lines when close to each other (low opacity).

- Every 1–2 seconds a random node fires: it flashes `--fire` and a pulse of light travels along its connections to neighbors, which may fire in turn (small chance, so it never explodes).
- **Interactive:** the mouse cursor acts as a stimulus. Nodes within ~150px of the cursor brighten; clicking fires the nearest node and starts a visible chain reaction.
- Title text stays perfectly readable: keep nodes sparse and dim behind the text column (density mask on the left 45%).

**Acceptance criteria**
- [ ] Clicking anywhere on the background triggers a chain reaction that is visible from a distance.
- [ ] Clicking on the background does NOT advance the slide on this slide (title slide exception; navigation by keys only).
- [ ] 60 fps; animation stops when the slide is not active.
- [ ] Reduced motion: static network, click still flashes the nearest node.

### T04 — Biological neuron with threshold (slide 3)
An SVG drawing of one neuron in `--stain`: branching dendrites on the left (5 branches), a round cell body in the middle, a long axon to the right ending in terminals. Hand-built organic shapes with smooth curves, not clip-art.

**Interactive behavior**
- Each of the 5 dendrite tips is clickable (large hit area, at least 60px). Clicking sends a `--dapi` pulse traveling along the dendrite to the cell body.
- Inside the cell body: a **charge meter** (a fill level or a ring that fills up). Each arriving pulse adds charge. Charge slowly leaks back down over ~1.5s if nothing else arrives.
- A dashed line on the meter marks the **threshold**. When charge crosses it: the cell body flashes `--fire` with bloom, a bright pulse races down the axon, the terminals sparkle, and the charge resets.
- Result: one click is not enough. Three quick clicks make it fire. This is the "aha" for the audience.
- Small label near the meter: "threshold".
- An "auto" toggle button: random signals arrive by themselves, so the presenter can talk while it runs.

**Acceptance criteria**
- [ ] One click never fires the neuron; 3 clicks within about a second always do.
- [ ] Leak is visible: clicks spaced 2 seconds apart never fire it.
- [ ] Pulses visibly travel (not teleport) along the curved paths.
- [ ] `R` resets charge and stops auto mode.

### T05 — Connection strength: the café (slide 4)
Show four input sources on the left, each connected by a synapse line to one "attention" neuron on the right (same visual style as slide 3, simplified).

Sources (labels in speech-bubble shapes): "chatter", "music", "dishes", "your name!".

**Interactive behavior**
- Each source emits its signal at random intervals (the café is noisy). Each signal travels along its synapse line. The line thickness and brightness show connection strength.
- The neuron uses the same charge/threshold mechanic as slide 3, with charge added = signal × connection strength.
- Initially all four connections are equal and weak: the neuron never really fires, the name gets lost in the noise.
- Each source has a vertical slider under it: "connection strength" 0–1. Dragging changes line thickness live.
- A primary button **"Learn from experience"**: animates over ~2 seconds the "your name!" connection growing thick and bright, while the others fade to thin. After that, whenever "your name!" emits, the neuron fires; the others barely move the meter.
- Clicking a source manually emits its signal immediately (so the presenter can "say the name" on cue).

**Acceptance criteria**
- [ ] Before "Learn from experience": the neuron fires rarely or never in 10 seconds of noise.
- [ ] After: every "your name!" signal makes it fire; noise signals alone almost never do.
- [ ] Sliders and the button stay in sync (the button moves the slider thumbs too).
- [ ] `R` returns to the equal, weak starting state.

### T07 — Train the real model (offline, Python)
Write `training/train.py` that trains a small MLP on MNIST and exports it for the browser.

- Architecture: **784 → 64 → 32 → 10**, ReLU on hidden layers, softmax output. Small enough to draw every hidden neuron on slide 7.
- Framework: PyTorch (CPU is fine). Dataset via `torchvision.datasets.MNIST`.
- **Data augmentation is mandatory**, because hand-drawn mouse digits differ from MNIST: random rotation ±12°, random translation ±3px, random scale 0.85–1.15, random stroke thickening/thinning (dilate/erode with p=0.3).
- Train ~15 epochs, Adam, lr 1e-3. Target test accuracy **≥ 97%**.
- Log test accuracy per epoch.
- Export to `js/model/weights.js`:
  - Weights and biases as Float32 arrays encoded in **base64** strings, plus shapes, assigned to `window.NN.data.weights = {...}`.
  - Also export the per-epoch accuracy list to `window.NN.data.trainingLog = [...]` (used on slide 8).
- `training/samples.py`: export 10 clean test-set digits, one per class 0–9, to `js/model/samples.js` (`window.NN.data.samples`), each as an array of 784 floats rounded to 2 decimals.
- `requirements.txt` and a short section in `README.md` on how to retrain.

**Acceptance criteria**
- [ ] `python training/train.py` runs end to end and writes `weights.js`.
- [ ] Test accuracy ≥ 97% printed at the end.
- [ ] `weights.js` is under 400 KB.
- [ ] Both generated files have a header comment: generated, do not edit.

### T08 — Drawing pad and the tensor (slide 6)

- Keys `0`–`9` load sample digits into the pad and grid.

**Acceptance criteria**
- [ ] The preprocessed grid of a drawn digit looks like an MNIST digit (centered, similar size).
- [ ] Drawing with a finger on a touchscreen works and does not scroll or navigate.

### T09 — The network in action (slide 7, the main event)
Full-width visualization of the real trained model running live in the browser.

**Layout, left to right**
- Drawing pad (smaller, ~300px) with "Clear" button. Pre-filled with the digit from slide 6 if there is one; otherwise sample "7".
- Input layer: the 28×28 grid (not 784 separate circles).
- Hidden layer 1: 64 neurons in a column (two columns of 32 if needed). Hidden layer 2: 32 neurons.
- Output layer: 10 neurons labeled 0–9, each with a horizontal **probability bar** and percentage to its right.
- Small labels under each layer: "784 inputs", "hidden layers", "10 answers".

**Behavior**
- `js/model/mlp.js`: decode base64 weights once, run the forward pass in plain JS (matrix-vector loops on Float32Array). Must take < 5ms.
- Neuron brightness = activation (normalized per layer), using the `--fire` interpolation. The top output neuron gets the full bloom glow.
- Connections: drawing all 50k is unreadable. Draw only the **strongest contributions** for the current input: for each neuron in layer n+1, the top 3 incoming (weight × activation) connections. Color by sign, opacity by magnitude.
- **Propagation animation:** after each stroke ends (and on "Run again" button), light pulses travel layer by layer: input → hidden 1 → hidden 2 → output, ~250ms per layer. Neurons light up when their layer is reached. Probability bars grow at the end with easing.
- **Live mode** toggle (default on): while drawing, bars and neuron brightness update in real time without the pulse animation, so the audience sees the answer change as the digit takes shape (draw "1" then extend it into "7").
- **Inspect:** hovering a hidden neuron dims everything else and shows its 28×28 incoming-weight pattern as a small heatmap tooltip (`--dapi` positive, `--cherry` negative). This shows "what this neuron looks for".
- Keys `0`–`9` load sample digits.
- Answer readout near the output: large digit with "96%" next to it. If max probability < 50%: show "Not sure" instead and the top two guesses.

**Acceptance criteria**
- [ ] Correct prediction for all 10 samples.
- [ ] Reasonable predictions for mouse-drawn digits (test at least 3 drawings per digit; ≥ 80% correct).
- [ ] Pulse animation clearly goes left to right, layer by layer.
- [ ] Live mode updates without lag while drawing.
- [ ] Hover inspect works on every hidden neuron.
- [ ] 60 fps on the slide during animation.

### T10 — How it learns (slide 8)
Left column: the toolkit list, revealed **one item per fragment**:
1. **Training data**: 60,000 labeled handwritten digits
2. **Loss function**: a score of how wrong the answer was
3. **Backpropagation**: finds which weights caused the mistake
4. **Gradient descent**: nudges those weights a little
5. **Epochs**: repeat the whole thing many times

Right side: a **learning cycle diagram** (5 nodes in a loop: data → prediction → loss → backpropagation → update weights → back to data). Each fragment lights up the node matching the list item. After the last fragment, a pulse starts circulating around the loop continuously.

Below the cycle, two small interactives (tabs or side by side, whatever fits better):

**A. Roll down the hill (gradient descent toy)**
- A 1D curve (a smooth loss landscape with one global minimum and one shallow local minimum). A ball sits on it.
- Click anywhere on the curve to place the ball. "Step" button moves it one gradient step; "Play" runs steps continuously.
- Slider "step size" (learning rate). Small: slow and steady. Large: the ball overshoots and bounces chaotically. This shows why tuning matters, without any math on screen.
- Ball color shifts from `--cherry` (high loss) to `--fire` (low loss).

**B. Accuracy over epochs**
- Line chart of the real `NN.data.trainingLog` from T07, drawn progressively when the tab opens (line animates from epoch 1 to the last). Y axis: "accuracy", X axis: "epoch". Final value labeled.

**Acceptance criteria**
- [ ] Fragments reveal list items and the cycle nodes in sync, reverse correctly.
- [ ] Large step size visibly overshoots; small step size converges.
- [ ] Chart uses the real training log, not invented numbers.
